# X5 SDK 关节、复位和电机参数

本目录提取的是项目固定版本 **Python SDK 的实际控制参数**，包括其闭源
`libarx_x5_src.so` 内的常量。原始 double 数值保存在 `parameters.json`；
STM32 使用的单精度只读表在 `../c/x5_sdk_parameters.h/.c`。
查阅和验证不需要连接机械臂。

## 6 个关节

位置采用 SDK/URDF 坐标，单位 rad；编号从机械臂底座向末端排列。
下表限幅由 `statePositionControl` 使用，末端控制也检查同一范围。
GO_HOME 直接使用配置的复位目标，没有经过这一位置限幅流程。

| 关节 | CAN ID | SDK 电机类型 | 位置下限 | 位置上限 | 默认复位角 | Kp | Kd | Ki | PROTECT 的 Kd |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| J1 | 1 | MotorType4 | -2.618 | 3.14 | 0 | 150 | 1 | 50 | 1 |
| J2 | 2 | MotorType4 | -0.1 | 3.6 | 0 | 150 | 1 | 50 | 4 |
| J3 | 4 | MotorType4 | -0.1 | 3.0 | 0 | 150 | 1 | 50 | 4 |
| J4 | 5 | MotorType2 | -1.57 | 1.57 | 0 | 50 | 0.8 | 0 | 1 |
| J5 | 6 | MotorType2 | -1.57 | 1.57 | 0 | 25 | 0.8 | 0 | 1 |
| J6 | 7 | MotorType2 | -1.97 | 2.08 | 0 | 10 | 1 | 0 | 1 |

Kp、Kd 是 SDK 写入混合控制命令的增益，不是电机固件内环 PID。
Ki 是 SDK 额外加入前馈 effort 的位置误差积分系数：Kp>0 时累加
`(q_cmd-q_feedback)/200`，积分状态限制在 ±5；Kp≤0 时清零。
PROTECT 下 Kp、位置、速度、前馈 effort 为 0，只保留上表阻尼 Kd。
重力模式下六轴 Kp/Kd 都为 0，effort 为重力补偿结果；夹爪调用 CatchSoft。

这些关节参数没有按 arm_type=0/1/2 分支修改，适用于本二进制的三个模型入口。
型号间的重力模型差异仍由重力模块处理。

## 复位姿态与插值参数

| 来源 | J1 | J2 | J3 | J4 | J5 | J6 |
| --- | --- | --- | --- | --- | --- | --- |
| SDK 构造默认值 | 0 | 0 | 0 | 0 | 0 | 0 |
| ROS1 remote_master 示例 | -0.112 | 0.948 | 0.858 | -0.573 | -0.105 | 0.097 |
| ROS2 v2_collect 示例 | 0 | 0.948 | 0.858 | -0.573 | 0 | 0 |

后两行来自 `reference/` 中保留的原始 YAML，只是不同应用配置，不能根据机械臂
型号自动选择。`setHomePositions` 可以改写六轴目标。复位不是编码器设零。

`stateGoHome` 传入插值函数的加速度参数为 0.08，速度参数为 0.2，第三参数为 200。
到位判断要求六轴都满足 `abs(q-q_home)<0.08` 和 `abs(v)<0.1`。
普通位置控制的插值参数默认是 0.5、2.0；`arx_x(a,v,third)` 将前两个参数除以
1000 后分别限制在 [0,0.5]、[0,2]，此二进制没有使用第三个参数。
**Interpolation 实际忽略传入的第三参数，位置更新使用固定 float 0.03 乘速度。**
因此不能把这里的 200 当作已实现的 5 ms 插值周期。这里只保存参数和证据，
没有将厂商插值或状态机移植到单片机。

## 第 7 个电机：夹爪

CAN ID=8，MotorType2。SDK 为夹爪分配的通用上下限是 [0,5]，但
`CatchPositionCtrl` 不使用这两个值，实际行为如下：

| 参数 | arm_type=0/1 | arm_type=2（2025） |
| --- | --- | --- |
| 工作方式 | 位置误差生成 effort，或用户指定 effort | 电机位置控制 |
| 位置限幅 | 该函数未显式限制 | [-3.4,0.1] rad |
| Kp / Kd | 0 / 0.2 | 2 / 0.1 |
| effort | clamp(8×(home+target-0.1-feedback), -2,2) | 0 |
| 初始化速度命令 | -5 rad/s | +2 rad/s |
| 初始化 Kp / Kd / effort | 0 / 0.2 / 0 | 0 / 0.2 / 0 |

2025 夹爪另检查反馈 current>1.2：连续计数>50 且目标大于实际位置时，将目标
改为实际位置+0.4。这个改写发生在 [-3.4,0.1] 限幅之后，原 SDK 未再次限幅。

夹爪初始 home 存储值为 0；初始化计数>699 后，用当时反馈位置覆盖 home，
2025 入口还发送设零命令。初始化完成后的制动命令 Kp=0、Kd=2、其余为 0。
`getJointPositons()` 的第七项为反馈位置减该 home 参考值。
因此 C 表明确标记夹爪 home 为运行时量，没有提供假的固定复位角。

## 电机协议可表示的参数

| SDK 参数 | MotorType4（J1–J3） | MotorType2（J4–J6、夹爪） |
| --- | --- | --- |
| 编码位置范围 | [-12.5,12.5] rad | [-12.5,12.5] rad |
| 编码速度范围 | [-18,18] rad/s | [-45,45] rad/s |
| effort 命令/反馈范围 | [-30,30] | [-10,10] |
| Kp 范围 | [0,500] | [0,500] |
| Kd 范围 | [0,50] | [0,5] |
| 位置量化 | 16 bit | 16 bit |
| 速度、effort、Kp、Kd 量化 | 12 bit | 12 bit |
| 普通命令 DLC | 8 | 8 |
| 反馈 CAN ID | 与电机 ID 相同 | 0；data[0] 低 4 bit 匹配电机 ID |
| 反馈错误字段 | data[0] 低 5 bit | data[0] 高 4 bit |
| 超时阈值 | 100000 μs | 本机 ID=5–8 使用 800000 μs |

以上是协议/软件范围，**不是额定速度、电流或额定力矩**。
`GetMotorMsg` 将同一个解码 effort 数值同时写入 `torque` 和 `current`，
没有进行力矩常数或减速比换算，因此反馈 current 不能据此确认为真实安培。
`ifTorqeLimit` 对六轴的该字段取绝对值，与 13 比较，连续达到 200 次触发保护；
夹爪虽然存储了 13，却不参与此检查。MotorType2 的解码范围只有 ±10，故正常解码
的 J4–J6 数值本身不可能越过 13，不能依赖这项检查实现这些轴的实际过流保护。

MotorType4 初始位置偏置=0，反馈包装阈值为 [-13,13]，越界用 ±2π 修正一次；
反馈跳变超过 ±12.5 时计圈，每圈累加 25。发送位置使用
`q-offset+wrap_flag*2*pi` 再限制到 ±12.5。计圈累加的 25 和范围修正的 2π
是两个不同步骤，按原实现分别记录。
MotorType2 同样在反馈跳变超过 ±12.5 时计圈，每圈累加 25。

两种普通命令的字节排列不同。尤其 MotorType4 对 Kd 做 12 bit 量化，
实际打包只留下 **低 9 bit**；C 数据同时记录量化位宽和打包位宽，不擅自修正。
MotorType4 温度字段按整数 `(data[6]-50)/2` 解码，本版本未用于控制。
MotorType2 的 `online()` 对 ID≤4 另有 200000 μs 阈值（本机械臂没有这种映射），
超时后只置 false，没有在恢复时显式置 true。

MotorType2 管理帧发给电机 ID，DLC=8，前七字节 FF，最后一字节分别为：
使能 FC、失能 FD、设零 FE、清错 FB。
MotorType4 的“使能”和“失能”实际上调用普通控制命令：
使能 Kp=0/Kd=5；失能传入 Kd=100（随后被限制为 50），位置/速度/effort=0。
不能据函数名推断它关闭了功率输出。设零帧 ID=0x7FF，DLC=4，数据为
`00 motor_id 00 03`；其清错实现继承基类，返回空帧。
这些都是参数资料，不包含 CAN 发送功能。

## 其他限制与资料边界

三个 URDF 的六轴 limit 都是 lower=-10、upper=10、effort=100、velocity=1000，
它们与实际控制器限幅不同。末端笛卡尔约束另为：
下限 `[0,-0.53,-0.53,-1.745329252,-1.483529864,-1.483529864]`，
上限 `[0.53,0.53,0.53,1.745329252,1.483529864,1.483529864]`，前三项 m，后三项 rad。
旧版 ROS2 PDF 的关节限位还与本 Python 二进制不同，本模块不混用不同版本表。

当前 SDK 没有给出每个电机的商品型号、减速比、力矩常数、额定电压/电流/力矩、
峰值力矩、编码器精度、固件内环 PID、每台实机的零位标定。
JSON 将这些列为 `unknown_motor_parameters`；不能从 MotorType2/4 名称或协议
最大值反推出这些物理参数。“所有参数”的覆盖范围是上述可确认的 SDK 软件参数。
