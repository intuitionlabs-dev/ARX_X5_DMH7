# 上位机 SDK 手册

用 Python（或任何能开串口的语言）控制 **CtrBoard-H7** 控制板上的 **ARX X5 双臂**。

**先记这一条**：板子拒绝你的命令时是"当没收到"，没有报错也没有反馈帧 —— 见第 8 节。

`0x12` 这样的编号是**板子认的命令号**，括号前面的名字才是它的作用。

## 1. 硬件长什么样


```
  你的电脑
     │  一条"链路"：板子自己的 USB 口，或者一个 USB 转 RS485 的串口适配器
     ▼
  CtrBoard-H7 控制板（STM32H723）
     │  CAN 总线 1 ──→ 机械臂 A：6 个关节电机 + 1 个夹爪电机
     │  CAN 总线 2 ──→ 机械臂 B：6 个关节电机 + 1 个夹爪电机
```

- **一台板子、两条 CAN 总线、两台臂**。两条总线互相独立：一台臂掉线不影响另一台。
  （CAN 是板子和电机之间那两根线，拧在一起传差分信号的总线 —— **你不用碰它**，它不在上位机这一侧。）
- 每台臂 7 台电机：6 个关节（从根部到末端编号 j1…j6）+ 1 个夹爪。
- **上位机到板子只有一条链路**（板载 USB 口或 RS485 适配器，二选一，板子出厂就定死了）。
  两台臂的命令都从这一条口子进出 —— 记住这件事，第 11 节（多臂）和第 12 节（线程）里全靠它。
- 帧里带一个 `arm_id` 指明这一帧是给哪台臂的：**`0` = CAN1 = A 臂，`1` = CAN2 = B 臂**。

## 2. 术语表


**粗体**是后面正文里最常出现的写法。

| 词 | 一句话解释 |
|---|---|
| **臂** | 一台六轴机械臂。本手册里"臂 A / 臂 B"就是 CAN1 / CAN2 上那两台。 |
| **关节** | 臂的 6 个转动轴，编号 j1…j6；SDK 里轴号 `0..5`。 |
| **夹爪** | 装在臂末端的抓手，自己一台电机；SDK 里轴号 `6`。 |
| **使能 / 失能** | 电机"使上劲"（能按指令走、能托住重量）/"松劲"（臂会在重力下掉下来）。 |
| **档位**（mode） | 整台臂的工作方式：**run**（位置控制，按你的指令走）／**阻尼**（能推动，像泡在油里）／**重力补偿**（不给指令也托着不动）／**停**（等于失能）。 |
| **状态**（robot_state） | 板子自己的流程位置，共 8 个：等待握手 / 离线等待 / 待初始化 / 初始化中 / 正常运行 / 通信离线 / 校准零点（设零期间）/ 复位中。见第 4 节的状态转移表。 |
| **初始化**（`0x02`） | 让板子把臂收回参考姿态并顺带把夹爪找零；跑完进入"正常运行"。见第 8 节的闸门。 |
| **复位位姿** | 臂的参考姿态：6 个关节 `(0, 0.5, 0.5, 0, 0, 0)` 度。**和"零点"不是一回事。** |
| **零点** | 角度 0 的位置。出厂在电机里写好，`0x10` 可以覆盖它。 |
| **找零** | **夹爪专用**的一次动作（初始化里顺带做）：推到一头限位 → 退回半个行程 → 把中点记成夹爪的 0。 |
| **标定** | 夹爪的"电机角度 ↔ 实际开口多少米"的实测换算（第 9 节）。**和"设零/找零"完全是两件事。** |
| **命令帧 / 反馈帧** | 你发给板子的帧 / 板子主动发回给你的帧（后者每秒 250 帧，描述"我现在什么样"）。 |
| **type_id** | 帧里的"这一帧是干什么的"编号，例如 `0x02` = 初始化、`0x16` = 位置控制。 |
| **payload** | 帧里除头尾之外的有效数据（也可能是空的）。 |
| **arm_id** | 这一帧是给哪台臂的（`0`/`1`）。 |
| **链路** | 你的电脑到板子的那一条串口/USB 连接。两台臂共享它。 |
| **闸门** | 板子给每条命令设的前置条件。不满足就**静默丢弃**（第 8 节）。 |
| **保活** | 板子 500 ms 收不到任何有效帧就切阻尼并退回"离线等待"。所以你得持续发包 —— **SDK 不会自动发包**（第 12 节）。 |
| **原始角 / 开口** | 夹爪电机的角度（线上是度）/ 两个爪子之间的实际距离（米，要标定）。 |
| **SI** | SDK 对外一律用国际单位：rad、rad/s、m、℃。线上是度，SDK 替你换（第 7 节）。 |
| **软限位** | 板子在软件里给每个关节定的角度上下限，超过就把你**夹在**限位上。见第 13 节第 6 条。 |
| **遥控器** | 另一套能直接操纵这台板子的手持设备（遥控发射机 + 板上的接收机）。它在线时会把命令挡掉、把档位抢走，而**它的在线状态查不到** —— 见第 8 节。 |

## 3. 你和板子之间怎么对话


**两种帧，一条链路。** 你发命令帧，板子回反馈帧。

- **握手**：连上以后你得先发一帧"版本帧"（`0x01`，带 4 字节版本码）。板子**只认**
  `Intuition-ARX-X5-2023-v0.2` 这一个版本（版本码 `0xF91DD3C9`）；对不上的输入它
  **一个字节都不回**，而且此后什么都不发 —— **只能复位板子**。所以别手改这个码；
  反过来说，握手成功本身就证明芯片上跑的就是这一版固件。
- **收到第一帧反馈才算真的通了**：板子在握手成功之前一帧都不发（`Arm.connect()` 等的就是它）。
- **帧长什么样**（SDK 全包了，这里只是让你看得懂日志）：
  `头部 6 字节：AA 55 │ type_id │ payload 长度 │ arm_id │ crc8`，然后是 payload，
  最后 2 字节 crc16 收尾；整帧长 = `8 + payload 长度`。字节流会粘包、会从中间断开，
  靠 CRC 校验重同步 —— 这些脏活 `sdk.protocol.FrameParser` 在做。
- **量**：板子正常工作后**每秒回 250 帧反馈**（每台臂各 250）。你怎么用这些反馈看第 12 节。

具体每一帧的编号、payload 布局、线上单位，见第 10 节的表。

## 4. 一次会话的生命周期


状态一共 8 个，编号就是反馈帧里的 `robot_state` 字段（名字表见 `board_defs.STATE_NAME`）。
一次会话只会沿着下面这些转移走：

| 起点 | 触发 | 终点 | 同时发生 |
|---|---|---|---|
| `0 等待握手` | 收到版本码相符的版本帧 `0x01` | `1 离线等待` | 板子从这一刻起才开始发反馈帧 |
| `0 等待握手` | 收到版本码不符的 `0x01` | 停在 `0` | **一个字节都不回**，此后什么都不发，只能复位板子 |
| `1 离线等待` | 7 台电机全部上线 | `2 待初始化` | 档位落 `停` |
| `2 待初始化` | 收到初始化 `0x02` | `3 初始化中` | 档位落 `run` |
| `3 初始化中` | 初始化跑完（夹爪同时找完零） | `4 正常运行` | 档位落**阻尼**（要再发 `0x12` 才进 `run`） |
| `4 正常运行` | 收到复位 `0x18`（且 7 台全在线） | `7 复位中` | 走一段约 2 s 的轨迹 |
| `7 复位中` | 轨迹跑完 | `4 正常运行` | 档位落阻尼；关节停在复位位姿 |
| `2 待初始化` | 收到设零 `0x10` | `6 校准零点` | 只管 j1~j6，不含夹爪 |
| `6 校准零点` | 设零跑完 | `2 待初始化` | 几秒后补发一帧 `0x11` 反馈帧 |
| 收到过有效帧之后的**任意状态**（`0` 和 `5` 除外） | 500 ms 内没再收到任何有效帧 | `5 通信离线` | 档位切阻尼 |
| `5 通信离线` | 收到任意有效帧 | `1 离线等待` | **要重新初始化**，它不会自己回到 `4` |

三处容易踩的：

- **只有收到第一帧反馈才算握手成功**（板子握手前不发帧）—— `connect()` 等的就是它。
- 上电后的常规路径是 `0 → 1 → 2`，**要到 `2` 才能发初始化**（闸门见第 8 节）。
- 链路断了不要紧（拔线、串口崩也行）：落点是 `5 → 1`，回来以后按 `2` 那一步重来。

## 5. 安装


Python 3.8+，跑真机只需要 pyserial：

```bash
pip install -r sdk/requirements.txt      # 就一行 pyserial>=3.5
```

`import sdk`、协议层、离线自测**不 import pyserial**（只有 `Link.open()` 才 import），
所以没有它的机器照样能跑自测、也能写只碰协议层的代码。仓库没有打包脚手架，
从**仓库根目录** `import sdk` 即可。

## 6. 快速开始


```python
import sdk, time

arm = sdk.Arm(0)                 # arm_id 0 = CAN1 上的 A 臂，1 = CAN2 上的 B 臂
arm.connect()                    # 开串口 → 发版本帧（握手）→ 等这一台的第一帧反馈
print(arm.robot_state_name, arm.joint_angles)    # 关节角，单位 rad

arm.wait_for(lambda a: a.robot_state == 2)       # 等到「待初始化」
arm.init_arm()                                   # 初始化（先看第 8 节的闸门！）
arm.wait_for(lambda a: a.robot_state == 4)
arm.start()                                      # 切进 run 档；控制帧只在这个档被接受

while True:
    # 夹爪目标三选一：gripper_m=0.03（要标定过）/ gripper_raw_deg=-141.5（不用标定）/ 都不给 = 保持当前
    arm.send_ctrl_pos(arm.joint_angles, gripper_m=0.0)   # 照抄当前角度、夹爪闭合
    time.sleep(0.01)                                     # 这一帧本身就算保活
```

两台臂（**必须共享一个 `Link`**，原因见第 11 节）：

```python
link = sdk.Link(); link.open()
a, b = sdk.Arm(0, link), sdk.Arm(1, link)
a.connect(); b.connect()
```

帧接口一个不落都在 `Arm` 上，签名和闸门见第 10 节。

## 7. 单位约定


| 量 | SDK 对外 | 线上 |
|---|---|---|
| 关节角 | **rad** | deg |
| 关节角速度 | **rad/s** | deg/s |
| 夹爪开口 | **m**（要标定，见第 9 节） | — |
| 夹爪原始角 | `raw_gripper_angle_deg` / `gripper_raw_deg=` | deg |
| 温度 | ℃ | ℃（uint8） |

**原始夹爪角是唯一的例外**：它是**电机的原始角**，双向都不做"电机角 → 关节角"的换算
（那几张换算表只有 6 个关节有），所以想要"米"就只能标定。`snapshot()` 是**同一帧**里换算好的
一致视图；单独读 `arm.joint_angles` 再读 `arm.mode` 是两次读，中间可能夹进一帧新的。

## 8. 闸门：板子默默丢弃你的帧


**板子对所有命令的回绝方式都是"当没收到"** —— 没有"我拒绝了"的反馈帧、没有错误码，
发送函数也照样返回成功。"没抛异常"不等于"板子受理了"。

`Arm` 的每个命令方法在发包**之前**做同样的预检，不通过就抛 `GateRejected` 并说清缺哪一条；
`force=True` 跳过预检（**只跳过客户端预检，跳不过板子**）。预检先看手里那帧反馈有多旧，
超过 100 ms 直接抛 `FeedbackStale`，绝不拿旧状态猜。

| 命令 | 板子受理的条件 |
|---|---|
| `init_arm()` 初始化 `0x02` | 状态是**待初始化(2)** **或**（正常运行(4) 且档位在 停/阻尼），**且** 7 台电机全在线，**且** 6 个关节（不算夹爪）与复位位姿偏差 ≤ 20° |
| `set_zero()` 设零 `0x10` | 状态是**待初始化(2)** |
| `start/gravity/stop/damping` 四个档位 `0x12..0x15` | 状态是**正常运行(4)** |
| `send_ctrl_pos/pos_vel` 控制 `0x16/0x17` | 状态是**正常运行(4)** **且** 档位是 **run** |
| `reset()` 复位 `0x18` | 状态是**正常运行(4)** **且** 7 台全在线（**故意不查姿态** —— 臂歪着才要收） |

**上面每一条还都要求「遥控器离线」**（遥控器见第 2 节术语表）。而它在线还是离线**不在任何反馈帧里**，所以
**客户端预检查不到这一条** —— 唯一的表现是"发了没反应"或者"档位被遥控器覆盖掉了"。
遥控器在你手上时，先把遥控器关掉。

初始化要求的参考姿态是 `board_defs.RESET_POSE_DEG = (0, 0.5, 0.5, 0, 0, 0)` 度，
容差 `ROBOT_INIT_POSE_TOL_DEG = 20` 度（这就是上面表里那个 20°）。发初始化之前
自己看一眼 `arm.joint_angles`。

## 9. 夹爪标定


夹爪是一台**达妙 DM4310 电机**（总线上编号 8，用厂商自己的控制模式 —— 这些都是板子那一侧
的事，你只需要知道它和 6 个关节的电机不是同一种）。反馈里的夹爪角是**电机原始角（度）**，
而**仓库里没有任何"多少度 = 多少毫米"的规格**，所以米数只能实测：

```bash
python3 -m sdk.calibrate_gripper --arm-id 0 --full-open-m 0.085
```

工具会连上、显示状态，然后 `d` 切阻尼（或 `x` 失能）**用手把夹爪掰到两端**，各按一次键记
下来，回车存进 `sdk/config/gripper_calib.json`：

- `FULL_OPEN` 是**你预先配置的参数**（完全张开时的开口距离，米，>0），代码里不写死量程。
- `0` 记「这里 = 0 m」，`f` 记「这里 = FULL_OPEN」，之后按这两点线性映射。
  **方向和尺度完全由这两个点决定**，工具不预设哪端是张开 —— 装反了也不用改代码。
- 也可以用 `r` 进 run 档后 `←`/`→` **点动**（按原始角的方向，不是"张开/闭合"的方向），
  但 run 档整条臂都使能着，手不好够的时候再用。

**必须在一次成功的初始化之后标定**：夹爪的零点是行程中点（∓142°），而那个零点只有找零
才会建立 —— 在那之前原始角的零点是没有含义的。工具会查反馈帧里夹爪的"已初始化"标志位并在
开头警告。**之后再跑任何 `0x10` 设零或再找零，零点会挪，标定作废要重标。**

没标定的时候 `arm.gripper_opening` **抛 `GripperNotCalibrated`**（不是返回一个猜的数），
而 `arm.raw_gripper_angle_deg` / `gripper_raw_deg=` 一直可用。标定文件是本机实测数据，
仓库 `.gitignore` 忽略 `*.json`，**不要提交**。

## 10. 帧接口参考


`↑` 上位机发，`↓` 板子发。payload 全是小端。头部 6 字节 =
`AA 55 | type_id | datalen | arm_id | crc8`，尾 2 字节 crc16；整帧长 = `8 + datalen`。
`crc8` = CRC-8/MAXIM 盖头 5 字节，`crc16` = 反射多项式 `0x8408`（初值 `0xFFFF`）盖头+payload。

| type_id（简称 tid） | 方向 | payload | 线上单位 | SDK 方法 |
|---|---|---|---|---|
| `0x01` | ↑ | 4 B：u32 版本码 | — | `send_version()` / `keepalive()` |
| `0x02` | ↑ | 0 | — | `init_arm()` |
| `0x10` | ↑ | 0 | — | `set_zero()` |
| `0x11` | ↓ | 12 B：u8 state + u8[7] result + u32 用时 ms | — | `wait_setzero_ack()` / `last_setzero_ack` |
| `0x12` | ↑ | 0 | — | `start()`（进 run 档） |
| `0x13` | ↑ | 0 | — | `gravity()` |
| `0x14` | ↑ | 0 | — | `stop()`（**失能、松劲**） |
| `0x15` | ↑ | 0 | — | `damping()` |
| `0x16` | ↑ | 28 B：f32[6] 关节角 + f32 夹爪角 | deg | `send_ctrl_pos()` |
| `0x17` | ↑ | 52 B：f32[6] 关节角 + f32[6] 关节角速度 + f32 夹爪角 | deg, deg/s | `send_ctrl_pos_vel()` |
| `0x18` | ↑ | 0 | — | `reset()` |
| `0x80` | ↓ | 63 B：4×u8 + f32[6] + f32[6] + f32 + u8[7] | deg, deg/s, ℃ | `arm.feedback` / `snapshot()` |
| 其它 | ↑ | 任意 | — | `send_raw(tid, payload)` —— **总逃逸口**，无预检无换算 |

`0x80` 的 4 个 u8 依次是 `mode`（档位） / `robot_state`（状态） / `motor_lost_mask`（掉线掩码）
/ `motor_inited_mask`（已初始化掩码），后面是 6 个关节角、6 个关节角速度、夹爪原始角、
7 个温度。掩码 **bit0..5 = j1..j6、bit6 = 夹爪**。`0x80` 板子侧**实测 250 Hz**。

几个容易踩的点：

- `0x14 stop()` 是**失能**（电机无力）。
- `0x18 reset()` 走一段若干秒的轨迹回复位位姿，**不做夹爪找零**，跑完停在**阻尼**。
- `0x10 set_zero()` **覆盖电机的原零点**（把"当前位姿"定义成零点）；只管 j1~j6，
  夹爪不在默认参与集里。**没有即时反馈帧**，结果走几秒后的 `0x11`。
- `0x11` 的 `result = 1（未确认）` **不是故障**：它表示"帧发了、位置本来就在容差内"，
  臂本来就停在零位上时必然是它。

## 11. 多臂


```python
link = sdk.Link(); link.open()
a, b = sdk.Arm(0, link), sdk.Arm(1, link)     # 或 link.arm(0) / link.arms()
```

- **必须共享一个 `Link`**。两个进程、或一个进程里两个 `Link` 抢同一个串口设备，会把帧拆散
  （`device reports readiness to read but returned no data`）。
- 帧头的 `arm_id` 决定给哪一台：`0` = CAN1 = A 臂，`1` = CAN2 = B 臂。**没有广播**，
  越界的 `arm_id` 板子**直接丢**（SDK 侧也丢并计数 `link.stats["n_bad_arm"]`）。
- 一个 `Link` 可以同时驱动两台，各自的反馈槽、序号、`wait_*` 完全独立。

## 12. 线程与反馈帧


- `Link` 开一根 **RX 后台线程**：`read → FrameParser → 按 arm_id 分发`。**RX 线程里不调
  用户回调**（慢回调会饿死收帧），你只能主动读或 `wait_*` 轮询。
- 每臂一把锁，反馈是整对象替换的（`Feedback` 是不可变对象），所以拿到手的那份永远不会
  被改写。但**两次独立的读可能跨帧** —— 要严格一致就用 `snapshot()`。
- 发帧持一把**写锁**（pyserial 的 `write` 多线程不保证整帧原子）。
- **保活不自动发**：SDK 不起保活线程。你的周期控制帧本身就是保活；其余场景自己
  `keepalive()`。**板子自己发的反馈帧不算"收到的帧"。**
- `0x11` 没有请求 id，只能按序号等：`set_zero()` 会记下发送前的序号，
  `wait_setzero_ack()` 等序号更大的那一帧（默认 25 s，超时抛 `TimeoutError`）。
- 读写失败后属性会停在旧值 —— 用 `link_up` / `feedback_age` / `feedback_ok` 判活，
  可以 `link.reopen()`。

## 13. 注意事项


1. **静默丢弃，没有"我拒绝了"的反馈帧。** 没有异常 ≠ 板子受理了。`send_*` 只保证字节写出去了，
   受理与否看**下一帧反馈**（`robot_state` / `mode` 变没变）。`force=True` 不是"一定成功"，
   是"我不管预检了"。
2. **遥控器在线状态查不到**（不在任何反馈帧里），但它是**每一条命令**的隐含前提。
   发了没反应、或者档位被莫名其妙覆盖 → 先确认遥控器关了。
3. **不要绕过 `Arm` 直接 `send_raw()` 发已知的帧** —— 预检是唯一能提前告诉你"这条过不了"
   的东西。`send_raw` 是给板子加了新包时用的。
4. **500 ms 隐式保活**：任何有效帧都算，包括版本帧。断了落到**离线等待(1)**，
   **必须重新初始化**，不会自己回 正常运行。
5. **切档会作废上一帧控制指令**（板子收到切档就把上一条控制指令丢掉，防止把切档前的旧目标
   灌进位置环猛拽一下）。`start()` 之后要**重新发**控制帧。
6. **软限位要自己夹。** 板子那边确实会夹，但**只对已经初始化过的电机生效**
   —— 没初始化过的电机不受保护，而且是**静默**夹的，你从期望角上看不出来。
   用 `board_defs.clamp_axis(axis, value)`（返回 `(值, 是否夹过)`）。限位：
   min `(-115, 0.5, 0.5, -90, -90, -112.87)`°、max `(90, 206.26, 171.88, 90, 90, 119.17)`°。
7. **夹爪没有力矩/力控命令** —— 控制帧只带角度。夹爪软限位 ∓142° 也**只在夹爪找零成功后**
   （反馈帧里夹爪那个"已初始化"标志为真）才生效。
8. **`0x10` 会覆盖原零点**，跑之前先把臂摆到基准位姿；它也会让夹爪的标定作废。
9. **`0x14 stop()` 是失能**，臂会靠重力掉。
10. **温度区分不了"真 0 ℃"和"没数据"**（板子把无效值写成 0）。
11. **协议里没有递增计数/时间戳，检测不了丢帧。** 走 RS485 那条线时两个方向共用同一对线，
    上下行撞上就会丢（实测约 20%）。
    SDK 只能按到达时间判陈旧（`feedback_age`）。
12. **串口按身份挑，不按名字**：板子自己的 USB 口（身份 `0483:5740`）优先，其次是常见的
    CH340 适配器（`1a86`，走 RS485），**J-Link 的 SEGGER 虚拟串口（`1366`）会被拒绝**。`list_links()` 看现状。
    别写死 `/dev/ttyACM*` 这种名字 —— 换一次适配器就失效。
13. **标定文件不要提交**，那是本机的实测数据。

## 14. 离线自测


```bash
python3 -m sdk.selftest          # 不需要硬件、不需要 pyserial
```

165 项：CRC 参考值 + 位运算参考实现逐字节比表、整帧字节锚点、编解码往返、切帧重同步、
按 `arm_id` 分流、单位往返、夹爪标定模型、**闸门矩阵**（逐条断言该挡的挡了、该发的发了什么）、
**假板子状态机**（`sdk.sim`：握手闸门、时序、两台不串台、看门狗、`--fake-lost`）、
以及**与固件头文件对拍**（码表、限位、状态个数、档位顺序 —— 仓库在的时候才跑，
所以 `sdk/` 被拷出去单用也不会失败）。改协议或改板侧常量之后先跑它。

## 15. 文件清单


| 文件 | 职责 |
|---|---|
| `__init__.py` | 包入口，只 re-export；`import sdk` 不碰 pyserial、不起线程 |
| `errors.py` | 异常层级（单独一个文件，免得各模块互相 import） |
| `protocol.py` | 协议层：CRC / 版本码的 FNV 哈希 / 码表 / 组帧 / `FrameParser` / payload 编解码（**线上单位**） |
| `board_defs.py` | 板侧常量镜像：软限位、复位位姿、状态 / 档位名字表 |
| `units.py` | 度 ↔ rad 换算策略 |
| `link.py` | 串口 + RX 线程 + 按 `arm_id` 分流 + 写锁 + 口子挑选 |
| `arm.py` | `Arm`：全部帧接口 + 闸门预检 + 单位换算（**SI**） |
| `sim.py` | `SimLink`：假板子，两台臂的模拟状态机 + 闸门 + 看门狗 |
| `gripper.py` | 夹爪两点标定：m ↔ 原始度的映射 + JSON 存取 |
| `calibrate_gripper.py` | 交互式标定工具 |
| `selftest.py` | 离线自测 |
| `config/` | 运行期数据（`gripper_calib.json`），由工具自动创建 |

异常层级（`errors.py`）：根是 `ArError`，下面分 `LinkError`（`NotConnected` 是它的子类）、
`ProtocolError`、`GateRejected`、`FeedbackStale`、`GripperNotCalibrated`、`CalibrationError`。
`GateRejected` 的消息里会写清楚缺哪一条闸门，直接 `print` 就能给人看。
